## 6B. Report Section — Live-Hosting Chat Limitation

Use the following formal English text in your report. It is written to describe the observed deployment limitation accurately without claiming that the chat module itself is incomplete.

### Suggested Report Heading

**Realtime Chat Deployment Limitation on Free Hosting**

### Suggested Report Paragraph

“The MarketLink application includes an order-based customer–farmer chat module. In the local XAMPP environment, the chat module operates successfully: messages are stored in the database, users can access only conversations linked to their own orders, and the interface can retrieve and display the latest messages.

For realtime updates, the deployed version is designed to use Pusher Channels. After a message is saved, the PHP backend sends a signed event to the Pusher HTTP API using cURL. The customer and farmer browser pages subscribe to an authenticated private order channel and refresh the relevant conversation when that event arrives.

During deployment on the InfinityFree free-hosting environment, realtime chat delivery could not be reliably demonstrated. The free-hosting environment may restrict, block, or intermittently affect outbound API/cURL requests required for the server-to-Pusher event trigger. If the Pusher credentials are not configured, or if outbound cURL access is unavailable, the realtime event cannot be delivered. This is a hosting and third-party connectivity limitation rather than a database or local application-logic failure.

The system includes a manual Refresh option as a fallback, so stored messages can be synchronized when the hosting environment allows the normal application request. For a production deployment, the recommended solution is to use hosting that permits stable outbound HTTPS/cURL connections, configure valid Pusher App ID, Key, Secret, and Cluster credentials, and confirm that the Pusher private-channel authorization endpoint returns a successful response. The complete realtime chat workflow has been tested successfully on XAMPP localhost.”

### Short Version for a Viva / Presentation

“The chat module works on XAMPP localhost. On InfinityFree free hosting, the realtime Pusher event depends on an outbound cURL request from PHP to Pusher. Free hosting can restrict or make this API connectivity unreliable, so realtime delivery could not be demonstrated there. This is a deployment limitation; the local application logic and database messaging flow work correctly. A manual Refresh fallback is included, and stable paid hosting or a VPS would resolve the realtime deployment issue.”

### If Asked: “Why Does It Work on Localhost?”

“XAMPP runs on our own local machine, where PHP cURL and outbound HTTPS requests are under our control. Therefore, the backend can contact Pusher normally. On free shared hosting, the provider controls these server capabilities and may limit outbound connections to prevent abuse.”

### If Asked: “How Would You Fix It in Production?”

“I would deploy the same application to reliable PHP hosting or a VPS with outbound HTTPS and cURL enabled, put valid Pusher credentials in `config/pusher.php`, and verify that the private-channel authorization endpoint and Pusher event trigger both return successful responses. The existing code already supports this architecture.”
